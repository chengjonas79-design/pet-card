# 萌宠联萌 · 微信 H5 裂变增长落地方案（2026Q1）

## 1. 文档目标

本方案用于统一“宠名片”H5版本的增长执行路线，目标是用最小研发成本跑通以下闭环：

1. 公域短视频引流
2. 微信内 H5 测试与分享
3. 邀请裂变与奖励解锁
4. 进入私域（企微/社群）
5. 可追踪的转化归因与复盘优化

约束条件：
- 暂不做小程序，只做 H5。
- 技术部署统一走腾讯云 CloudBase（云函数/数据库/静态托管或云托管）。

---

## 2. 北极星指标与阶段目标

### 北极星指标（单一）
- `每100个落地访问，带来多少个有效私域线索`

### 核心业务指标（按漏斗）
1. `landing_uv`：到达 H5 的独立用户
2. `photo_uploaded_rate`：上传照片率
3. `card_generated_rate`：名片生成率
4. `share_click_rate`：点击分享按钮率
5. `share_to_open_rate`：分享后被打开率
6. `invite_completion_rate`：被邀请人完成测试率
7. `private_lead_rate`：留资/进群/加企微率
8. `k_factor`：每位用户带来的新用户数

### 4周目标（建议）
1. `photo_uploaded_rate >= 70%`
2. `card_generated_rate >= 60%`
3. `share_click_rate >= 25%`
4. `invite_completion_rate >= 20%`
5. `private_lead_rate >= 12%`

---

## 3. 增长策略：一套核心能力 + 两个入口壳

不是做两个独立工具，而是同一系统两种入口：

1. 微信内入口（主战场）
- 分享卡片进入 H5
- 完整体验：测试 -> 出结果 -> 奖励 -> 进私域

2. 公域入口（短视频承接）
- 视频挂链接/二维码进入同一 H5
- 先给结果，再引导领取深度权益（进入私域）

统一内容：
- 同一前端工程（Vue + Vite）
- 同一云函数（CloudBase）
- 同一数据库（events / user_profiles）
- 同一埋点口径与归因模型

---

## 4. 用户路径设计（必须打通）

### 路径A：微信内裂变路径
1. 用户A打开 H5，上传宠物图生成名片
2. 用户A点击分享，带 `inviter_id/share_id` 转发
3. 用户B从分享链接进入并完成测试
4. 系统给 A/B 双边奖励（模板/权益）
5. 用户B在结果页被引导入私域（企微/社群）

### 路径B：公域短视频导流路径
1. 用户在短视频看到案例内容
2. 点击链接或扫码进入 H5
3. 快速完成测试并拿到可晒结果
4. 领取扩展权益时进入私域
5. 在私域触发二次分享与活动复访

---

## 5. 功能优先级（按增长贡献排序）

## P0（必须先完成）

### P0-1 可传播结果页（社交货币）
结果页一次生成 3 种可分享素材：
1. 宠物名片图（高颜值）
2. 趣味结论卡（如“社交型/护主型”等）
3. 对比挑战卡（“我家 vs 你家”）

验收标准：
- 用户在 10 秒内可看懂并能直接分享
- 至少一个素材支持“长按保存”
- 分享文案可一键复制

### P0-2 邀请奖励机制（完成后发奖）
规则：
1. 用户分享链接带 `share_id + inviter_id`
2. 被邀请人“完成测试”后算有效邀请
3. 达到阈值解锁权益（1/3/5人）

奖励建议：
1. 邀请1人：解锁高级模板
2. 邀请3人：解锁同城曝光位/专属称号
3. 邀请5人：解锁优先进群或线下活动抽签资格

### P0-3 私域承接页标准化
结果页必须出现明确 CTA：
1. 加企微领取“7天宠物成长建议”
2. 进群领取“同城养宠地图/活动通知”
3. 留手机号/微信号领取“定制宠物档案”

验收标准：
- CTA 按钮点击率可统计
- 每个渠道来源可归因到私域线索

### P0-4 渠道归因参数统一
进入链接参数标准：
- `src`（来源：wx_group / wx_moment / douyin / xhs）
- `campaign`（活动名）
- `content_id`（视频或素材ID）
- `share_id`（分享实例）
- `inviter_id`（邀请人）

---

## P1（P0稳定后上线）

### P1-1 挑战型玩法（比“漂流瓶”更可控）
建议优先做：
1. 同城宠物挑战榜（每周主题）
2. 品种社交挑战（柯基周/金毛周）
3. 节日挑战（春节装扮、春游打卡）

理由：
- 晒图成本低，理解成本低
- 可结合短视频话题
- 审核风险低于陌生人聊天/漂流瓶

### P1-2 分享后二次激励
1. 分享后返回页显示进度条
2. 告知“再完成X人可解锁下一奖励”
3. 触发提醒入口（公众号/企微消息）

### P1-3 内容运营自动化
按标签推送：
1. 猫/狗
2. 品种
3. 城市
4. 新用户/活跃用户/邀请达人

---

## P2（可选探索）

### P2-1 宠物相亲（轻量版）
先做“卡片匹配”，不做即时聊天：
1. 提交“交友意向”
2. 系统推荐 3 个潜在匹配名片
3. 引导去群内互动

### P2-2 漂流瓶
仅建议在有稳定审核和风控能力后再做，不建议作为近期主路径。

## 6. CloudBase 技术实现（H5架构）

## 前端
- 框架：Vue 3 + Vite
- 托管：CloudBase 静态托管（或云托管）
- 路由：保持现有页面结构，重点优化结果页与分享链路

## 云函数（现有基础上扩展）
1. `breed-identify`：识别（支持 mock 兜底）
2. `track-event`：埋点上报
3. `user-profile`：建档、邀请绑定、奖励进度、私域意向

新增建议：
4. `reward-center`（可合并到 `user-profile`）
- 校验有效邀请
- 发放奖励状态
- 防重与风控

## 数据集合建议
1. `events`：全量行为埋点
2. `user_profiles`：用户资料与状态
3. `invite_relations`（可选）：邀请关系明细
4. `reward_logs`（可选）：奖励发放记录
5. `private_leads`（可选）：私域线索池

## 8. 4周实施计划（可直接执行）

## 第1周：打透 P0 核心链路
1. 重做结果页素材（3种可分享卡）
2. 统一分享文案和链接参数
3. 对齐埋点字段与看板口径
4. 验收：从 landing 到 share_opened 全链路可跑通

## 第2周：奖励与私域承接
1. 上线完成后发奖机制（1/3/5）
2. 打通私域 CTA（企微/群/表单）
3. 防刷规则上线（设备/IP/频控）
4. 验收：invite_completed 和 private_lead_submitted 稳定入库

## 第3周：公域短视频联动
1. 为短视频批量生成 `campaign/content_id` 链接
2. 上线 10 条素材做A/B测试
3. 按渠道看“进私域成本”和“邀请效率”
4. 验收：可输出渠道级ROI周报

## 第4周：增长优化冲刺
1. 优化分享素材点击率（封面/标题/文案）
2. 优化奖励门槛（1/3/5 vs 1/2/4）
3. 优化私域承接页转化文案
4. 验收：至少2项核心指标提升20%以上

## 9. A/B 测试矩阵（首批）

1. 结果页首屏主标题
- A：趣味人格导向
- B：社交挑战导向

2. 分享奖励门槛
- A：1/3/5
- B：1/2/4

3. 私域 CTA 文案
- A：领资料（理性）
- B：领福利（感性）

每个实验最少跑满：
- 1000 landing_uv 或 3 天（取先到）

## 10. 合规与风险控制

1. 不做“强制分享后才能继续”
2. 不做诱导现金裂变文案
3. 明示隐私用途与删除入口

## 13. 结论

在“只做 H5”的前提下，本方案可以实现完整的获客裂变闭环。  
当前阶段最关键不是继续加新功能，而是把这三件事做到极致：

1. 结果页可传播
2. 邀请奖励可兑现
3. 私域承接可归因

只要三件事打通，公域短视频投放就能持续放大，形成稳定增长飞轮。
